## 1. Cómo leer las clases

| Clase | Qué significa para el cargador |
|---|---|
| `directo` | Copia 1:1 a la columna indicada, con el saneo que diga la transformación. |
| `despivot` | Una columna del legado se convierte en **varias filas** destino (una por período). |
| `derivado` | No se copia: se calcula, se descompone o se resuelve una clave foránea. |
| `catalogo` | Alimenta una tabla catálogo (cuentas, terceros, tipos, comprobantes). |
| `procedencia` | Sin semántica acreditada: se guarda **crudo** en `migracion_filas.valores_originales` con su motivo. No se le inventa columna. |
| `pendiente` | **Requiere decisión** antes de cargar. Ver [`homologacion/PENDIENTES.md`](homologacion/PENDIENTES.md). |
| `fuera_nucleo` | Dato real sin destino en el núcleo contable (pertenece a otro módulo). |
| `descartado` | No se migra, y la transformación dice por qué. |

## 3. Transformaciones que más se equivocan

Estas nueve reglas atraviesan varias tablas: si una se aplica mal, el error es
silencioso y cuadra mal. Están detalladas en
[`02_consideraciones_previas.md`](02_consideraciones_previas.md) §4.

| Tema | Regla | Trampa documentada |
|---|---|---|
| Signo del valor | `TVALOR` > 0 → débito; `TVALOR` < 0 → crédito = `-TVALOR` (`MOVICON.prg:6581-6583`) | Conservar el original y las anomalías/ceros en staging; **nunca** perder el signo ni truncar. |
| Columnas mensuales | `MACMDEB01..18` / `MACMCRE01..18` se despivotan a una fila por período | **No perder los períodos `00` y `13..18`**: el destino los admite y el saldo no cuadra sin ellos. |
| Saldo de apertura | `MSALDO` y `MACMDEB00`/`MACMCRE00` pueden ser el mismo dato | Cargar el período `00` desde `MACM*00`; usar `MSALDO` sólo si `00` viene vacío (T11). |
| Porcentajes | `19` → `0.19` en el dominio de fracción | No dividir dos veces un dato que ya venga como fracción. |
| Fechas | Numéricas `AAAAMMDD` (`TFECHA`, `TFECDOC`, `DFECHA`, `CFCHCREA`) o texto → `date` | Blancos, cero o inválidas a cuarentena con motivo; **jamás** sustituir por la fecha de hoy. |
| Códigos y NIT | Texto, con ceros iniciales y valor original | Normalizar con tabla de equivalencias (patrón → id), no con sustituciones irreversibles. |
| Tercero sin auxiliar | `NITN` de 15 espacios **o** NULL equivale al NIT matriz | Es la regla que ya usa el backend hoy; no inventar un tercero genérico. |
| Códigos que parecen importes | `VISDOCUM.DEB01..09` / `CRE01..09` son **cuentas**, no débitos/créditos | Error de interpretación frecuente: van a `plantilla_lineas`, no a importes. |
| Clasificación | `CONMAE.CTCTABASE` **no** es `cuenta_base_id` | Va a `cuentas.clasificacion_corriente` (corriente / no corriente). |
| Importes | `numeric(18,2)` puede redondear | Conservar el valor original y registrar cada diferencia aprobada en `migracion_ajustes`. |
