Diseña y genera un prototipo web interactivo, de alta fidelidad y navegable, para una aplicación de contabilidad general empresarial llamada **CONTABDSI**. Debe conservar toda la funcionalidad del sistema legado VISION/FORTUNER, pero reorganizarla según el flujo moderno del contador. No copies la apariencia de Windows/FiveWin ni uses una estética anticuada. El producto debe sentirse profesional, denso, confiable y preparado para operación contable diaria.

Si este proyecto ya contiene un rediseño o hay pantallas/componentes de Figma adjuntos, extiéndelos: conserva marca, tokens, componentes, navegación aprobada y datos existentes. No reemplaces el proyecto completo. Usa la propuesta visual siguiente sólo para completar lo que aún no esté definido. Antes de cada iteración, identifica qué pantallas ya existen, qué requisitos faltan y cuáles vas a agregar.

### Propósito

La aplicación recibe hechos económicos por captura directa, lotes o importaciones; valida y contabiliza comprobantes; mantiene saldos por cuenta, tercero y centro de costo; permite trazabilidad documental; genera libros, estados financieros, impuestos y medios magnéticos; y ejecuta auditorías, reprocesos, cierres y consolidaciones.

El flujo principal es:

**Configurar → Capturar/importar → Validar → Aprobar → Contabilizar → Consultar → Conciliar → Informar → Impuestos/medios → Cerrar/consolidar.**

### Tecnología del prototipo

Genera una aplicación React + TypeScript con componentes reutilizables, datos mock en español y navegación completa. No conectes un backend real. Aísla los datos simulados en una capa de servicios. Simula validaciones, carga de archivos, trabajos en segundo plano, cambio de estados y confirmaciones. No ejecutes acciones destructivas reales. Organiza los componentes de forma modular.

La aprobación, reversión trazable, roles y simulación son requisitos propuestos del rediseño, no afirmaciones de que ya existan en el legado. Usa reglas tributarias configurables, sin inventar tarifas/topes legales. Para reglas no definidas muestra “Pendiente de validación funcional”. Diseña estados de conflicto de edición, bloqueo por otro usuario, doble envío prevenido, reintento seguro y error de transacción. La interfaz debe estar preparada para un backend con importes decimales, claves por compañía/año, permisos de servidor, control de versión, idempotencia y contabilización atómica; el prototipo sólo simula estos contratos.

### Diseño visual

Usa un shell desktop-first: sidebar plegable, header fijo y área central amplia. En el header deben permanecer visibles compañía, NIT, año, período, estado Abierto/Cerrado, búsqueda global, notificaciones y usuario. Usa fondo gris muy claro, tarjetas blancas, navegación azul petróleo, verde para cuadratura/éxito, rojo para errores y diferencias, ámbar para advertencias. Tipografía clara con números tabulares. Valores monetarios en COP alineados a la derecha. Densidad compacta con opción cómoda. Cumple WCAG 2.2 AA y navegación por teclado.

Optimiza para 1440 y 1920 px; permite consulta/aprobación en tablet. En móvil muestra tablero, consultas y aprobaciones, pero no fuerces la captura contable compleja.

Toda acción sensible debe mostrar y registrar usuario, fecha/hora, compañía, año, parámetros, impacto, resultado y motivo.

### Reglas contables

- Mostrar débito y crédito en columnas separadas; no pedir crédito negativo.
- Sólo contabilizar cuando débito = crédito.
- Período cerrado es sólo lectura.
- Cuenta no afectable no acepta movimiento.
- Tercero/centro/base son obligatorios según la cuenta.
- Fecha y documento deben concordar con el período.
- Detectar duplicados antes de contabilizar.
- Importación masiva pasa por lote; importación directa llena un borrador y exige validación antes de contabilizar.
- Anulación crea reversión trazable.
- Todo cambio de maestro/proceso masivo queda auditado.
- Acciones destructivas requieren permiso, respaldo y confirmación.
- Trabajos largos muestran progreso persistente y notificación.
- Acumulados desactualizados deben indicarse.

### Seguridad para acciones peligrosas

Aplícalo a limpieza de compañía, reasignaciones, eliminación masiva, reconstrucción, reindexación/compactación, traslado 13-18, cierre y consolidación.
